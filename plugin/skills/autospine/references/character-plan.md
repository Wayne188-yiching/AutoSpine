# Character plans — reference and runbook

A character is an **images-only** Spine 4.0 document (every image placed on one root bone), its PNG folder, and a **plan**: one JSON file holding every character-specific decision. The engine turns plan + images into an editable Spine 4.0 project and, when an artist version exists, measures the result against it. Design and evidence: [ADR-017](adr/ADR-017-character-plans-and-reference-acceptance.md). Schema: `CharacterPlan-0.1` in `schemas/src/character-plan.ts`.

The steps below need no code changes and can be run by any model or person who can edit JSON and call the CLI (or the MCP tools in brackets).

## Runbook

Work on copies. Never write into original artwork folders or an open Spine project with unsaved edits.

1. **Images-only input.** From an artist project export (Spine 4.0 JSON), strip everything but placements:

   ```text
   node <skill>/scripts/autospine.mjs strip-images artist.json images/ work/imagesOnly.json
   ```

   `images/` is the folder the art is in. Spine's JSON export writes no images: it is the project's own image folder, the export's `skeleton.images` path (for example `./image/`) taken from the `.spine` file's folder. This writes `imagesOnly.json` and `imagesOnly.strip-report.json`. Check that `summary.over2px` is empty (this is A1, ≤ 2 px). Sheared placements become 4-corner quads and are listed in `quadMeshForShear`. If there is no artist project, export the layered art to Spine as regions on the root bone; that document is the images-only input.

2. **Write the plan** next to it (`source.imagesOnly` and `source.images` are relative to the plan). Start from a working plan (the synthetic one in `tests/character-fixture.ts`, or a previous character) and edit the parts. Part names are the slot names, or `slot#attachment` for non-setup attachments.

3. **Lint until clean** [`autospine_lint_character_plan`]:

   ```text
   node <skill>/scripts/autospine.mjs lint-plan work/plan.json
   ```

   Exit 2 means errors. Each line names the block and the problem: unknown joint or part, parent planned later, an image with no mesh and no region bone, an unknown `$param`, a duplicate control id. Warnings flag unused parameters and start values outside their search range.

4. **Build** into a new folder [`autospine_build_character`]:

   ```text
   node <skill>/scripts/autospine.mjs build-character work/plan.json work/build-1 [--params=best-params.json]
   ```

   The plan is linted first. `build-record.json` holds the joints, face mixes, IK bend sides, `setupDeviationPx` (must be ≤ 0.5), each QA seam's drift (≤ 11 px) and inversions (0), and the hashes of the plan and images-only file. The folder imports straight into Spine 4.0.64 (`images/` sits beside the JSON). `HANDOVER.md` explains the file to whoever edits it next, and bones are coloured by role: main blue, control red, face followers orange, chains green (ADR-026).

5. **Compare with the artist version** [`autospine_compare_reference`] when one exists:

   ```text
   node <skill>/scripts/autospine.mjs compare-reference work/plan.json work/build-1 artist.json work/compare-1 [--animation=<name>]
   ```

   It compares the plan's animations that the artist file also has, so a full export of the artist's project works as it is; `--animation` compares one of them. The first lines say which were compared and which were left out: `artistOnly` (the artist's other animations) and `planOnly` (planned animations the artist has not made). An `--animation` the plan or the artist file lacks, or no animation in common, stops with `CLI_COMPARE_ANIMATION`. It prints one PASS/FAIL line per criterion and exits 2 if any fails. A1 counts the slots the compared animations show; A6 compares frame 0 with the artist's (ADR-024). Plan animations are loops, so the D1 critic uses phase-invariant chain metrics (ADR-020): `range:<probe>` and `lag:<probe>` replace peak time, overshoot and peak delay, and where the loop starts does not matter. `acceptance-results.json` has every measurement. In `compare-<animation>.png`, the top row is the artist version and the bottom row the build, at the same times.

   **Rest pose (pose-layout setups).** When the setup stacks several pose sets and the animation starts elsewhere, fit the rest pose to a reference image of that pose (a PNG covering `qa.view`, any scale) [`autospine_fit_pose`]:

   ```text
   node <skill>/scripts/autospine.mjs fit-pose work/plan.json work/build-1 reference.png work/pose.json
   ```

   Copy its `pose` into `motion.animations[].pose` and build again. Check `coverage` (below about 0.6, do not use the pose), `residual` and the parts marked `used: false`. Only the hips and IK targets translate, chains follow their parents, and expressions are not fitted (ADR-024, ADR-025).

   **Key poses from pictures (one-shots).** When the requester gives a few pictures of the motion (storyboard frames or frames of a reference video) instead of only a name, fit them as key poses [`autospine_fit_pose` with `references`]. Each picture is `<frame>=<file>`, covering `qa.view`:

   ```text
   node <skill>/scripts/autospine.mjs fit-pose work/plan.json work/build-1 0=f00.png 8=f08.png 14=f14.png 44=f44.png 60=f60.png work/keyposes.json --animation=Win --zero=0
   ```

   Build the plan first without the motion the name would have guessed (a jump, a wave): each picture is fitted over the build's pose on its frame, so the key poses add to the plan's breath, follows and waves (ADR-033). Copy `keyposes` into `motion.animations[].keyposes` and build again; a second run over that build refines them (the output includes the key poses the plan already had). Options:
   - `--zero=<frame>`: that picture shows a pose the build already has (frame 0, after its rest pose was fitted from it). It gives no key pose; what the matching reports for it is its own error on these drawings (a part the build bends differently) and is taken off the other pictures. Recommended whenever the frame-0 picture is the rest pose.
   - `--min-coverage` (default 0.6): pictures below it give no key pose, as for a rest pose. The summary lists each picture's `coverage`, `residual` and the parts left `unused`.
   - `--ignore=slot,...`: parts whose drawing changes between pictures (an expression's mouth, eyes, tongue) and should not place their bone.
   - `--ease` (default `ease`): the arrival ease written on the new keys.

6. **Review video** [`autospine_review_video`]: one MP4 per plan, every animation first with the mesh wireframe, then with the bones, then the plain motion; artist | build when an artist file is given, or reference video | build with `--reference-video=<file>` (a plan of one animation; the video's frame i beside animation frame i, its figure scaled and placed over the build's). Needs ffmpeg.

   ```text
   node <skill>/scripts/autospine.mjs review-video work/plan.json work/build-1 [artist.json] work/review.mp4 [--reference-video=ref.mp4]
   ```

7. **Compare with a reference video** [`autospine_compare_video`] when the requester has the motion as a video (ADR-034). Record it in the plan as `motion.animations[].reference: { video, start? }` (path relative to the plan; `start` is the second that shows frame 0), then:

   ```text
   node <skill>/scripts/autospine.mjs compare-video work/plan.json work/build-1 work/video-1 [--animation=Idle] [--video=ref.mp4] [--start=0.5]
   ```

   The build is placed over the video's figure and compared on every frame: V1 silhouette overlap (mean ≥ 0.9, minimum ≥ 0.8), V2 each part's position against where it shows in the video (median ≤ 0.6 %, p90 ≤ 1.5 % of the figure height), V3 whole-figure timing (lag ≤ 2 frames) and size (0.75–1.33), V4 the loop seam. It writes `<animation>/compare.mp4` (reference | build | difference ×4), `report.json` with `hints` in words, and `summary.json`; exit 2 means not passed. `report.json` `mirrored` lists asymmetric parts the reference draws the other way round for at least a tenth of the animation (ADR-035): on those frames the part's mirror image must match better than the part by at least half its asymmetry, so a part that is only redrawn (an expression, a deform) is not counted. The video needs a single-colour background (`CLI_VIDEO` otherwise). `deliver` runs it for every animation with a reference. Report a failure; the requester decides what to change.

   To have the video drive the motion instead (ADR-036) [`autospine_fit_video`], set `reference.use: "fit"` (then `deliver` fits first) or run:

   ```text
   node <skill>/scripts/autospine.mjs fit-video work/plan.json work/build-1 work/fit-1 [--animation=Idle] [--video=ref.mp4] [--start=0.5] [--rounds=3] [--every=1] [--ignore=Mouth,Eyes] [--no-zero] [--no-track] [--no-lag]
   ```

   It needs `plan.qa.view` and `motion.fps` (30 at the studio). Every frame becomes a picture over `qa.view`; the plan's guessed main motion is taken out (depth 0, no `keyposes`) and built as `base/`; each picture is fitted over the base's pose on its frame, frame 0 as the zero frame (fit the rest pose from it first). `summary.json` `zero.shifted` is the share of frame 0's matched parts (by area) drawn more than 1.5 % of the figure height from the build's frame 0; above a quarter the rest pose is off, and a hint names the parts. `zero.largestOffset` is the largest single bone offset on frame 0, usually the matching's own error on a look-alike part (a finger), which the zero frame takes off the other frames. Each part is followed from the frame before, forward and then backward through the clip (ADR-039): a bone the two passes disagree on (8 degrees or 2 % of the figure's height) is left as a gap on that frame, and `summary.json` `tracking` and the hints name it; `--no-track` fits every frame alone. `summary.json` `inputs` lists every file the run read, with its SHA-256. A loop's tracks are folded onto the period the video repeats with, over the first cycles that stay in step; the animation keeps its length, and `summary.json` gives the stretch and the shortest length that holds whole cycles. A one-shot's tracks are smoothed. Both become `keyposes` on shared key frames, at most twice the artists' key density (ADR-032) or four a folded cycle. A bone that trails or leads the bone it hangs from keeps that timing (ADR-040): its key poses play that many frames later, written as `keyposeLag`; `summary.json` `keys.lag` lists the lags and `--no-lag` keys every bone on the shared frames. Each `round-k/` holds `plan.json`, `build/` and `compare/`; later rounds refit the frames still above 0.6 % and rescale or re-time chain waves from the comparison (a chain moving its own way gets its root fitted). `best/` is the round with the lowest penalty; exit 2 means no round passed, and a refusal (frame 0 covering under 0.6, a clip too short) also exits 2 before fitting. Results are reference-fitted, not blind. Expressions, mesh deforms, scale, motion that only follows the main beat (sink scales, face slide, wave roots) and parts the video redraws are not fitted; `hints` name what is left. Keep a generated clip that redraws the figure as `use: "check"`.

8. **Tune motion** [`autospine_optimize_motion`] when D1/D2 fail. Run it in chunks:

   ```text
   node <skill>/scripts/autospine.mjs optimize-motion work/plan.json artist.json work/opt --budget=150
   ```

   | Exit | Meaning                                   | Next step                                                                 |
   | ---- | ----------------------------------------- | ------------------------------------------------------------------------- |
   | 0    | Passed (with margin, inside shrunk bands) | Build with `--params=work/opt/best-params.json`                           |
   | 3    | Paused at the budget                      | Run the same command again (it resumes)                                   |
   | 4    | Converged without passing                 | Rerun with `--seed=n`, widen `motion.search`, or change the motion blocks |

   Then build and compare again. The search only moves parameters listed in `motion.search`. Results tuned against the artist version are **benchmark-tuned**, not blind; say so when reporting.

9. **Deliver** into the project folder:

   ```text
   node <skill>/scripts/autospine.mjs deliver _work/plans/plan-NN.json _work/builds/build-NN <project-dir> [artist.json] --name=<Name>
   ```

   The project folder's top level gets exactly `<Name>.spine` (imported with the Spine 4.0.64 command line), `images/` (the images the project draws, copied from `source.images` or `--images=<folder>`, so `./images/` opens anywhere; nothing else from that folder) and `<Name>.mp4` (the review video, artist | build when an artist file is given). Working files live in `<project-dir>/_work/` (`init-project <project-dir>` creates `input/`, `plans/`, `builds/`, `checks/`, `notes/`); `deliver` lists anything else left at the top level as `stray`. With reference videos in the plan it also writes `<Name>-vs-reference.mp4` (`<Name>-<animation>-vs-reference.mp4` when the plan has several animations) and returns the V1–V4 rows and hints as `reference`; a comparison that cannot run is `referenceError` and does not stop the delivery (`--no-reference` skips it). Without the editor (`--spine`, `AUTOSPINE_SPINE` or the standard install) it writes `<Name>.json` for Import Data. Delivering again needs `--replace`, which moves the old project and video into the build folder. `_work/delivery.json` records the project's hash: a project that changed since it was delivered (edited in Spine) stops with `CLI_DELIVER_EDITED` unless `--force`. Deliveries from 0.5.7 and 0.5.8 kept it as `.autospine-delivery.json` beside the project, which Windows Explorer shows; it is still read, and the next delivery moves it. Without a record (before 0.5.7, or `_work/` deleted) a project saved more than two minutes after its video counts as edited. `strayImages` lists images in `images/` the project does not draw, left by an earlier delivery; they are kept.

10. **Hand off**: open the delivered project in the Spine editor (A5) and get an artist's review (E). Numeric acceptance is not artistic approval.

## Plan reference

### Joints

`joints` maps names to rules. A reference to another joint is its name or an inline rule. IR world is x right, y down, in pixels of the composed art.

| Rule         | Fields                                                  | Use for                                                                                 |
| ------------ | ------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `centroid`   | `part`                                                  | Mean of the opaque pixels: face anchors, small props                                    |
| `center`     | `part`                                                  | Centre of the image rectangle (placement, not pixels)                                   |
| `overlap`    | `parts: [a, b]`                                         | Centroid of where both images are opaque: neck, waist, a hair root                      |
| `end`        | `part`, `dir: [x, y]`, `band?` (px)                     | Mean of pixels within `band` of the extreme along `dir`: crown, sole                    |
| `axisEnd`    | `part`, `pick` (top/bottom/left/right/near/far), `ref?` | One end of the principal axis: shoulder / hand of a limb image. `near`/`far` need `ref` |
| `lerp`       | `a`, `b`, `t` (−4..4)                                   | Elbow, knee, points along a segment                                                     |
| `project`    | `point`, `a`, `b`                                       | Projection onto a line                                                                  |
| `narrowest`  | `part`, `a`, `b`, `range: [from, to]`                   | Thinnest cross-section between fractions of a–b: wrist, ankle                           |
| `domeCenter` | —                                                       | Centre of the measured face dome (needs `face`)                                         |
| `point`      | `at: [x, y]`                                            | Scene anchors only; never for anatomy                                                   |

`axisEnd` needs an elongated part. A round part (a head, a ball) has no principal axis, so use `end` with a direction.

`align { x, y }` takes the x of one joint and the y of another, for example a hip under its leg at the pelvis height (ADR-025).

### Bones

Bones are created in order, and a parent must come earlier.

- `{ id, parent?, at, to?, angle?, length? }`: a bone at joint `at` pointing to `to`, or at a fixed world `angle` (degrees, clockwise on screen; `-90` points up; `"art"` uses the plan's `artAngle`). `length` defaults to the distance to `to`.
- `{ chain: { part, bones, parent, from?, near?, prefix? } }`: `bones` bones along the medial line of a strand image, from its `top` (default) or `bottom` (on a horizontal strand: left or right), or from the end nearest joint `near` (ADR-023), named `${prefix}_1…n`. `prefix` defaults to the part name. Use it for hair, tails, ribbons, sleeves, boughs and hanging ornaments.

### Face

`face: { head, anchor, base, control, counter?, counterMix?, followers, pinMargin? }` measures a dome on the head image around `anchor`. The `control` bone moves the face surface. `counter` follows with `counterMix` (default −0.3). Each follower bone (eyes, brows, mouth) gets a local relative Transform whose mix is the dome value at its origin. Pins hold rings around eye holes to their follower's mix over `pinMargin` × head width (default 0.12). See ADR-012/016.

`face.layers: [{ bone, depth }]` adds 2.5D depth outside the face plate (ADR-018). Each bone follows the control with mix = depth × the dome peak, clamped to −1..1:

- depth 1 is the face surface;
- above 1 is in front (bangs, a hat brim);
- 0 rides the head;
- below 0 is behind and moves against the turn (back hair, a ponytail root).

Give bangs or back hair their own bone so they can be a layer. A follower or layer whose parent is rotated against the control's parent gets an aligned carrier bone `<id>_frame`, so it moves in the control's direction.

### Skeleton template (ADR-025)

Every bone runs from its joint to the next one, so chains are continuous and the bones view reads like the body:

| Region                      | Bones                                                                                                                                                                                                   | Joints                                                                         |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Ground                      | `base` under the pelvis                                                                                                                                                                                 | `align(x: pelvis, y: feet)`                                                    |
| Hips and torso              | `body` (main) at the pelvis; `spine` pelvis → chest; `chest` chest → neck base                                                                                                                          | pelvis between the leg tops; chest halfway                                     |
| Neck and head               | `neck` neck base → neck top; `head` neck top → crown                                                                                                                                                    | part overlaps                                                                  |
| Legs                        | vertical `stance` ground → pelvis, squashed with `sink: { kind: "squash", bone: "stance", track: true }`; per leg `thigh` (hip → knee) and `calf` (knee → ankle) on it; `foot` (ankle → sole) on `base` | hip `align(x: leg top, y: pelvis)`; knee = leg/sock overlap; sole = lowest end |
| Arms                        | from `chest`: shoulder → elbow → wrist → hand; hands on the body pinned by IK to `body`                                                                                                                 | part overlaps and ends                                                         |
| Soft strands                | 3-bone chains from the attached end: hair, ears, moustache, beard, tail, mane                                                                                                                           | `chain.from` / `chain.near`                                                    |
| Ornaments sharing one image | one 3-bone chain each, from where it hangs to its far end; `nearest` weights over all of them                                                                                                           | `end` per side                                                                 |

Weights follow the bones: a robe or skirt over the legs takes a gradient `base` → `spine` (the stance squashes the legs over the same span), pants chain weights on thigh and calf, sock and shoe a gradient calf → foot, the neck chest → head. Mesh a deforming torso denser than the artist median.

### Meshes and regions

`meshes[]: { part, mesh, weights }`, processed in order:

| `mesh.type` | Options                                                                                                                  | When                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `feature`   | `spacing`, `edgeLength`, `minHoleFraction`, `density: "artist"` / `"fine"`, `hullVertices`, `interiorVertices`, `deform` | Faces, bodies and anything with cut-outs (eye holes, windows). By default artist wiring (ADR-041): the hull has the opaque outline's corners at 3 % of √(width × height), times 0.67 for a rigid part, 0.9 on 1–2 bones, 1.5 on 3 or more (the bones of its weights); a part that bends (2+ bones, or `deform: true` for a part deformed by keys; parts in `motion.deforms` are marked automatically, ADR-042) also gets hull ×0.9 at least and interior points: rows across its joints and halfway along long bones, then spread points up to 0.27 × hull area / mean hull edge²; explicit `interiorVertices` sets that total; cut-outs kept as rings. `density: "artist"` covers cut-outs instead; `density: "fine"` (or `spacing` / `edgeLength`) is the engine's dense lattice, about 100 vertices whatever the size: only when B1/B3 fail with fewer |
| `contour`   | `intent` (chain/rigid/unknown), `cleanup[]`                                                                              | Most limbs and clothing; `cleanup` lists alpha-repair budgets tried in order (default 0.03, 0.1, 0.25)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `surface`   | `cols`, `rows`                                                                                                           | Thin strands and leafy parts; interior vertices bend without folding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `quad`      | —                                                                                                                        | Mouths, FX, sheared placements                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

| `weights.type` | Fields                                                  | Meaning                                                                                                     |
| -------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `chain`        | `bones[]` or `chain` (part), `blend?`                   | Joint-plane chain (ADR-014); blend width = `blend` (default 0.4) × the shorter adjacent bone                |
| `gradient`     | `from`, `to`                                            | Linear between two bone origins (ADR-015): torsos, eyelids, jaws                                            |
| `dome`         | —                                                       | Face dome with pins (needs `face`)                                                                          |
| `transfer`     | `sources[]`, `proxies?[{part, bone}]`, `maxInfluences?` | Copy from meshes planned **earlier** (ADR-013): glows, outlines, shadows; proxies stand in for region parts |
| `rigid`        | `bone`                                                  | Whole mesh on one bone                                                                                      |
| `nearest`      | `bones[]`, `maxInfluences?`, `smoothing?`               | Inverse distance to the listed bones' segments, smoothed (ADR-023): leaf clusters and other blobs           |

`meshing: { all: true }` meshes every region part an animation shows with artist wiring, rigid to its region bone (ADR-024, ADR-041: the rigid hull count and no interior points). Use it for every character: artists mesh every shown part.

`meshing.parts: { part: { hullVertices?, interiorVertices? } }` meshes chosen region parts with their own vertex counts, rigid to their region bone, with or without `all` (ADR-037). Give a part that deforms (a mouth) interior vertices: artist wiring puts a rigid part's vertices on the outline only.

`regions: { slot: bone }` puts region images rigidly on a bone. A sheared placement on a region slot becomes a rigid quad automatically. Every image needs a mesh (by key or slot) or a region bone, and lint reports any that has neither.

### Constraints

- `ik[]: { name, bones (1–2), target, mix?, bendPositive? }`: `"auto"` keeps the setup elbow side. The build also checks the setup on the official runtime and flips a bend that moves the setup by more than 2 px.
- `transform[]: { name, bones, target, mix*, local?, relative? }`: mixes are −1..1 and default to 0.

### QA and output

- `qa.seams: [[a, b]]`: mesh pairs measured for seam drift (against frame 0, along the visible seam: the later-drawn part's outline over the other, ADR-025) and inversions at `qa.at[animation]` seconds (default: half way).
- `qa.probes: { face, eyes, pupils, chain: [[name, part]], hand: [name, part] }`: parts sampled by the performance critic. The head width of `face` is the unit.
- `qa.deformExclude`: regular expressions for FX, glow and shadow parts that deformation QA ignores.
- `qa.view`: crop of the contact sheets, review videos and `fit-pose` references, in Spine world units (y up).
- `output.imagesPath`: the image folder written into the skeleton (default `./images/`).

## Pitfalls seen so far

- **Round parts and `axisEnd`.** The axis is arbitrary on round parts, and the joint lands off-centre. Use `end` with a direction.
- **Thin strands and contour meshes.** A contour mesh on a narrow strand has no interior vertices and can fold when the chain bends. Use `surface` (for example 2 × 10).
- **IK bend.** Spine's bend side flips when the setup elbow is nearly straight. `"auto"` plus the runtime check handles it; `build-record.json` records which side was used.
- **Transfer order.** Transfer sources must be meshed earlier in `meshes`.
- **Main timing.** The main beats must fit inside the cycle. Every animation's `frames` should be a whole number of cycles, otherwise the loop seam (A4) breaks.
- **FX in deformation QA.** Glows and shadows stretch by design, so list them in `deformExclude`; otherwise B3 compares them with the artist's character stretch.
- **Optimizer margin.** The optimizer searches inside bands shrunk by 5 %, so its own critic count is lower than the official one. Use `--band-shrink=0` to read the official count.
- **Idle shape.** Artist idles are symmetric breaths (10 of 11 seen idles, including the YoLu blind test): use `shape: "breath"` with `down` at half the cycle. The settle template's anticipation and hold put the beats in the wrong place for an idle. Artists may start a loop mid-breath; that phase cannot be read from the images.
- **Idle size (ADR-032).** With the main on the hips (ADR-025), breathe 0.06 head widths (8 batch idles: 0.017–0.141). The old 0.14 was measured on chests and torsos. Let the head travel further and later with a translate follow (`gain: 0.7, lag: 8`: 1.6–2× the hips, about 3 frames behind). Swing strands ±8° from the root, tips 2 frames per bone, and limbs ±2°. `loopRecipe("idle", unit)` in `@autospine/motion` returns these.
- **One-shots (ADR-032).** Start from `oneShotTemplate(name, { frames, unit, subject })`: measured keys for a `move` bone, alpha and secondary swings. Artists swing limbs about 40° and strands about 35° in character one-shots, tilt the figure about 15° and key every 6–9 frames; exits start at once and characters do not fade; props and logos keep their base still and fade. Several kinds rest on one or two arts (walk, level-up, look, exit), so treat them as starting points.
- **Prop and logo loops.** Keep the base still (four of four arts); move alpha, image sequences and effect parts.
- **Planted hands and held props.** A hand resting on scenery or on the body (a bar, a table, the floor, the forehead) barely moves with the body: pin it with an IK constraint whose target bone hangs on that thing's bone (`root`, `head`). A prop the character holds (a cane, a cup, a fan) is part of the hand: hang it on the hand bone so it rides with the hand, and treat the hand as free unless the prop also rests on scenery (a glass on a bar). Give a free hand `travel` about 0.4 (the range across characters is wide).
- **Props.** Rigid regions can pass the numbers but not the review video. Give trunks and boughs chains (`chain.near` the trunk top for boughs), leaf clusters an inner-end root plus four short control bones with `nearest` weights, hanging ornaments chains parented to their bough, and glows transfer weights (ADR-023).
- **Pose sets.** Check which slots each animation shows before planning: an animation may hide the setup pose and show a set that is hidden in setup. Rig that set (a hidden slot with one attachment can be named by its slot) and switch it with `show` / `hide`. Planning the setup set for such an animation leaves recall at 0.
- **Face slide.** Plan the face by `parallax` (head widths), not `y` px: the same slide gives 0.33–0.6 of it in eye parallax depending on the dome, and px rules overshot 1.8–2.7× on unseen characters. Start at the artists' median, 0.03 with `x` 0.2. Add `move` only when the face should hold between breaths (3 of 12 seen idles).
- **Saccades.** Only 4 of 11 seen idles saccade; add `keyed` looks with `move` only when the brief asks for them.
- **Lights and glows.** Scene light layers that breathe or flicker need `pulses` or `colors`; bone motion alone leaves them static and costs motion recall (C2).
- **Pose layouts.** A setup that stacks pose sets may not be any animation's pose (HorseYearFish: the idle's head sits half a head width left). Ask for a picture of the rest pose and run `fit-pose`; A6 checks it.
- **One-shots from a name.** A name does not say the motion: the batch's `Win` became a jump while the artist made a tongue-out head tilt (D1 5/45 one-shots). Ask for a few pictures of the key poses and fit them (`keyposes`, ADR-033).
- **What key poses cannot show.** They turn the plan's joints and move the hips and IK targets. A changed expression (face plate deform, a tongue out, squinting eyes), a part scaled, a hand the artist moved off its arm, and parts hidden under others are not fitted; a head whose expression changes may not be placed at all (its face parts out-vote the fur). Read `unused` per picture. An expression the art has no image for can be keyed by hand as a `deforms` block (ADR-037), or drawn and swapped (ADR-027).
- **Legs under a robe.** Shortening each thigh along its axis (`sink.legs`) slides splayed feet inward. Put the legs on a vertical stance bone squashed with `track: true`, feet on the ground bone, and weight the robe `base` → `spine` (ADR-025).
- **Bridging meshes.** A mesh across a bending joint hangs between the bones outside that joint: the neck from spine to head, a robe from base to spine. Weighted to the joint's own bone, its hidden end swings and opens the seam.
- **Soft strands.** Artists give a forelock, moustache, beard, ears and tassels 3-bone chains on artist-density contours, and wave the forelock and moustaches a little in idles. A rectangle grid (`surface`) reads as unfinished in the wireframe; prefer `feature` with `density: "artist"` and chain weights.
- **Vertex and key counts.** Artists mesh deforming parts only a little denser than the rest (the Pig's body 33 vertices, HorseYearFish's robe 65 and face 87): keep the default wiring, which follows the weighting bones (ADR-041), and give counts where a part folds. Keys stay sparse: the build re-keys every bone timeline within `motion.keyTolerance` (default 0.25 degree or px, ADR-038), so key poses fitted frame by frame do not leave a key on every frame.
- **Benchmark tuning.** Parameters tuned against an artist version describe that version. They are a starting point for a similar character, not a blind result.
