# 人工手感引擎流程（ADR-010…016）

日期：2026-10-08。以下參數來自木乃伊貓私有試作的實測與 `tests/` 合成案例，是起始值與量測方法，不是品質門檻，也不代表美術驗收。任何角色仍要在自己的動作中重新量測。

## 何時使用

角色需要接近人工的臉部轉向視差、眨眼、肢體彎曲接縫、跟隨部件的光暈，或需要緩動、停頓與跟隨節奏的動作時，依本頁順序呼叫 MCP 引擎工具。這 8 個工具都只在記憶體計算並回傳 JSON，不寫檔，也不代替組裝座標或控制方案。

| 工具                                | 用途                                                   |
| ----------------------------------- | ------------------------------------------------------ |
| `autospine_feature_mesh`            | 有挖空（眼窩、臉窗、嘴孔）的部件：輪廓外框＋鎖定的洞環 |
| `autospine_measure_dome`            | 由臉部 alpha 量測圓頂場（中心、半徑、峰值）與翻折上限  |
| `autospine_dome_weights`            | 臉層圓頂權重；可用 pins 讓眼窩跟隨眼睛組件             |
| `autospine_gradient_weights`        | 兩骨線性漸變：眼皮、下巴、布片                         |
| `autospine_chain_weights`           | 跨關節骨鏈權重，每個關節各自的混合寬度                 |
| `autospine_transfer_weights`        | 光暈、外框、陰影從底下部件轉移權重                     |
| `autospine_build_keypose_animation` | 姿勢表＋時間規則 → 稀疏、帶曲線的 AnimationSpec        |
| `autospine_measure_overlap`         | 指定姿勢下的重疊接縫漂移與每張網格的翻折數（數值 QA）  |

座標：引擎 IR 為圖片空間（+x 右、+y 下）。`autospine_feature_mesh` 的頂點落在 `part.bounds` 指定的座標；bounds 若是組裝後位置即為世界座標，否則由 host 轉換。圓頂、權重與 QA 工具都使用世界座標。大型網格或 rig 超過 1 MiB 時，由 host 設定 `AUTOSPINE_MCP_MAX_MESSAGE_MIB`（1–16）。

## 流程

1. **網格**
   - 有挖空的臉片與繃帶：`autospine_feature_mesh`。小於前景 1 % 的洞直接覆蓋；回傳的 `rings` 是洞緣頂點，後續做 pins。
   - 肢體維持既有輪廓網格。內部格點已試過會翻折，預設不加。
   - 光暈：圖片上約 40 px 一格的表面網格（`generateSurfaceMesh`，目前走 API／CLI）。
2. **臉部圓頂**（ADR-012、016）
   - 用臉底圖呼叫 `autospine_measure_dome`；`anchor` 給眼白中心。預設 peak 0.7、counter 0.1。
   - 骨架由方案建立：頭骨下放世界對齊的 control 與 counter 骨於場中心；counter 以 Transform mix −0.3 跟隨 control。
   - 眼睛組件（眼白、瞳孔、眼皮）以 `domeValue`（`autospine_dome_weights` 的 `points`）作為跟隨 mix，整組剛性移動。
   - 臉底與繃帶用同一場呼叫 `autospine_dome_weights`。眼窩洞環轉成 pins：value = 眼睛組件的 mix，margin = 0.12 × 頭寬。0.06 會在大幅甩頭時翻折。
   - Control 位移保持在 `foldLimit` 以內；超過會在臉緣翻折。
3. **眼皮**（ADR-015）：每片眼皮兩骨，上骨在不透明上緣、下骨在下緣，都是世界對齊的眼白子骨；呼叫 `autospine_gradient_weights`。姿勢表以量測的眼皮高度為單位，睜眼 −0.9。眼皮只在覆蓋眼睛時顯示。不要改用 smoothstep 或 alpha／deform 眨眼。
4. **四肢**（ADR-014）
   - 在關節相接的圖片共用同一條骨鏈與同一組寬度，呼叫 `autospine_chain_weights`。寬度為每個關節「較短相鄰骨長 × 0.4」；0.15 以下會翻折。
   - 只是蓋在關節上的部件（掌、飾物）保留自己的骨，不併入骨鏈。
5. **光暈與外框**（ADR-013）：來源取對應的底層網格（同名去掉尾端 `s`，或世界範圍重疊最多者），呼叫 `autospine_transfer_weights`。底層若是剛性 region，光暈也保持 region。
6. **動作**（ADR-010、011）
   - 先寫姿勢表：主要節拍（`beats`）＋規則：`follow`（延遲、疊加、鏡像側）、`saccade`（眼神跳動）、`settle`（拖曳後回彈）、`cycle`。
   - 每個控制只能有一個驅動來源。
   - 位移單位用量測的頭寬或眼皮高度。
   - 緩動名稱：linear、hold、ease、sine、out、in、drift。
   - **主要節拍的時間點可由引擎提供預設值**：`planBeats`（`@autospine/motion`）吃一份 MotionBrief（總長、fps、loop、依序的 phase：anticipation／travel／settle／hold／look／return，可選 snappiness／holdBias，皆有預設），輸出 `KeyposeSpec.beats` 用的幀號與建議 ease；`beatsFromBrief` 直接組成 beats 片段，姿勢值仍由呼叫方給。時間配置原則與推導寫在 `packages/motion/src/beats.ts` 檔頭。
   - 延遲鏈用 `planLagChain` 給 `follow` 的 lag：每層固定 2 幀（30 fps，隨 fps 換算，`snappiness` 縮短），與動作長度無關。這是 pig 與木乃伊貓人工檔的實測中位數（每層 1 與 3.3 幀）折衷，尾巴這類重的部件可能需要更長。
   - 循環動作裡 `return` 與 `travel` 同份量，兩者都用 sine，往復會對稱。固定間隔的震動不要寫成分段，改用 `cycle` 規則。
   - 若 brief、參考或使用者已指定時間點，仍以指定值為準；規劃器只在沒有指定時提供結構性預設。
   - **寫簡述前先做三項結構檢查**（2026-10-13 四次盲測歸納；只在已看過的素材上驗證過）：
     1. **循環裡有幾次**：人工 idle 每個週期 1.0–3.0 秒，中位數 2 秒（ADR-032 把上限從 2.4 改為 3）。用 `cycles: suggestLoopCycles(秒數)`，例如 4 秒 idle 寫兩次呼吸；寫完用 `reviewMotionBrief` 檢查。
     2. **哪一層會動**：每個動畫先決定本體動不動。
        - 道具或符號（雕像、棺材）的 Idle、升級（lv）、特效、眼睛類動畫，本體通常不動，只動特效層。
        - 道具、Logo 的循環（ADR-032，4 套美術）：底座不動（0–0.01 頭寬），動作在透明度（約 35% 的部件）、序列圖與特效部件。不要替底座加呼吸或上下浮動。
        - 角色的字幕或字母動畫（wild）也通常只有字在動。
        - 本體不動就寫單一 `hold`（沒有節拍），時間放在特效層。
        - 反應類動畫（shake、collect、hit）與角色 idle 本體會動。
     3. **哪些附屬是剛性的**：帽子、蝴蝶結、圍巾、領子、眼鏡、瀏海通常和本體一起動（延遲 0），不要建 `follow` 鏈，權重直接給父骨。耳朵、馬尾、長髮、辮子、尾巴、裙子、鍊子才用 `follow`。若人工明顯另有自己的節奏（裙襬、長髮常見 10–20 幀或反相），改用 `cycle`。
   - **燈光與 2.5D**（ADR-018）：
     - 場景的 additive 燈光層用 `motion.pulses` 做呼吸或閃爍，需要精確時間點時用 `motion.colors`。
     - 頭部的瀏海、後腦頭髮、馬尾根部、頭飾給自己的骨，再加入 `face.layers` 設定深度：前方大於 1、頭上 0、後方為負值。轉頭時各層的視差就會不同。
     - 跟隨骨的父骨方向和控制骨不一致時，引擎會自動加上對齊骨（`*_frame`）。
   - **角色 idle 的表演預設**（ADR-019；幅度與頭部依 ADR-032 修正）：
     - 規則量自 8 個角色的 11 段人工 idle；2026-10 批次再量了 7 套美術的 8 段 idle（ADR-032）。
     - **主循環用 `main.shape: "breath"`**，`down` 設在週期一半：
       - 11 段裡有 10 段上升與下降幀數相差在 2 幀內，週期多為 2 秒。YoLu 盲測也對了。
       - setup 姿勢是呼吸的一端，但人工的 frame 0 不一定在 setup。YoLu 從中途開始，第 13 幀才到 setup。相位看不出來，就讓 frame 0 = setup。
       - 方向按角色算約各半：Yuuna、YoLu 從 setup 往下沉；BaShouEnn、木乃伊貓往上。看不出來時用下沉（`depth` 為正）。
       - 不要套「預備→下沉→停住」的 settle 範本，那是一次性動作的形狀。
     - **主動作在臀部，幅度 0.06 頭寬**：
       - ADR-025 的主骨 `body` 在骨盆。批次 8 段 idle 的臀部起伏中位數 0.061 頭寬，範圍 0.017–0.141。
       - 舊值 0.14 是 ADR-019 量胸口、軀幹得到的，放在臀部時是批次人工的 2–8 倍。
       - 胸口和頭的起伏由下面的跟隨產生，不要加大主動作來補。
     - **頭比臀部走得多，晚幾幀**：
       - 人工的頭起伏是臀部的 1.64 倍（0.69–3.16），晚 3 幀（−1 到 10）。
       - 寫法：`follow: [{ id: "headT", bone: "head", channel: "translate", gain: 0.7, lag: 8 }]`，數值也可由 `loopRecipe("idle", 頭寬)` 取得。
       - 在已看過的老鷹、美洲豹、大野狼上重建：頭是臀部的 1.7–2.0 倍、晚 3 幀（樣本內，只驗算寫法）。
       - 舊規則「頭幾乎不延遲（中位數 0 幀）」是相對胸口量的，相對臀部不成立。
     - **軟的長條整條擺動**（耳朵、尾巴、頭髮、毛簇）：
       - 人工整條擺 16°（8–23°），尖端比根部晚 4 幀（0–26）。我們原本只彎尖端，整條只有 6°。
       - 單骨的毛簇用 `cycles` ±8°，相鄰毛簇錯開 2 幀。
       - 骨鏈用 `waves`：`rootGain` = 8 / depth（根部隨呼吸擺 ±8°）、`amp` 3、`step` 2。
     - **四肢 ±2°**：人工中位數 3.5°，最常動的一肢（翅膀、揮動的手）約 10°，可給它 ±5°。
     - **臉部視差以縱向為主**：
       - 人工眼睛相對臉的位移，縱向約 0.02–0.03 頭寬，橫向約縱向的 1/5。YoLu 也是 4.9 倍。批次的動物更小（0.010–0.013），但合併所有已看過的 idle，中位數仍約 0.03。
       - 臉部用目標視差，不要寫 px：`sink` 的 face 寫 `parallax: 0.03`（頭寬，人工中位數）、`x: 0.2`。引擎會依圓頂權重算出滑移量（ADR-022）。
         - 舊寫法 `y`（px）換算到視差的比例因角色而異（0.33–0.6），兩次沒看過的角色都過大（1.8、2.7 倍）。
         - 12 段人工 idle 裡，6 段臉隨呼吸連續滑動，3 段大多停住、偶爾移動。預設用連續滑動。
         - 只有簡述或參考顯示臉大多停住時，才加 `move`（4–6 幀），讓臉在節拍後移到位再停住。
     - **預設不加眼神掃視**：
       - 11 段裡只有 4 段有掃視，其餘瞳孔只隨臉漂移。YoLu 盲測主動加了，3 項瞳孔指標全錯。
       - 只有簡述、參考或使用者要求「看向」時才加：瞳孔或亮點給自己的骨（掛在 `eyes` 下），用 `keyed` 加 `move`。每次 4–5 幀、ease `out`，其餘時間停住；結尾沒回位時引擎會補。
     - **手分兩種**：
       - 手靠在**場景的固定物**或身體上（吧台、桌面、地面、額頭）：用 IK 固定。目標骨掛在那個東西的骨上，例如 `root` 或 `head`。
       - 手**握著角色自己的道具**（拐杖、杯子、扇子）：道具掛在手骨上，跟著手走，不要固定在地上。
         - 道具的手就是自由的手；道具若同時靠在場景上（BaShouEnn 的酒杯靠著吧台），才固定手。
         - 薑餅人的拐杖原本固定在地上，人工則讓拐杖跟著手和身體一起沉 22 px。
       - 自由的手：與身體同相位。用 `follow` 的 `travel`、`to: <手骨>`，lag 0–3 幀；正值代表跟身體同方向。
         - 相對身體的位移中位數約 0.4，但範圍很大：從薑餅人舉起的手幾乎 0，到身體的 2 倍，光看圖片無法預測。先用 0.4。
         - YoLu、薑餅人的 D2 分別從對照的 0.105、0.071 升到 0.674、1.0。
     - **關鍵幀與緩動**：人工 idle 每 20 幀一個鍵（12–45），緩動約各三成 in-out、out、in。
   - **套用上面三項結構檢查後**，在四組已看過的資料上：
     - 節拍 F1 從 0.248 到 0.282；延遲在 panda、Yuuna 首次勝過「每層 1 幀」與零延遲。
     - 這只是在已看過資料上的符合度，不是驗證；一次動作（非循環）的段落結構仍是最大誤差。
7. **編譯與往返**：`autospine_compile_character` 會原樣保留每個鍵的曲線；host 另存到新目錄，用官方同版本 CLI 匯入／匯出。

## 道具（樹、植物、吊飾）的骨架與網格（ADR-023）

- 不要整片用剛性 region：搖錢樹用 32 骨、0 網格通過了數字驗收，但佈線和骨架遠不如人工。
- 範本（量自搖錢樹，樣本內）：
  - **樹幹**：2 骨鏈，網格用骨鏈權重。
  - **樹枝**：4 骨鏈，`chain.near` 指向樹幹頂，從靠樹幹那端長出；網格用骨鏈權重。
  - **葉叢**：根骨放在內側端、指向重心，再加上下左右 4 根短控制骨（重心到邊緣的 1/2～3/4），網格用 `nearest` 權重。
  - **吊飾**（銅錢、流蘇）：從上方長 4–5 骨鏈，掛在離吊點最近的樹枝骨上，網格用骨鏈權重（blend 0.45）。
  - **發光、閃光、光暈層**：transfer 掛在所屬部件的網格上。
  - **動作**：樹幹擺、樹枝波動、葉叢擺動加控制骨顫動、吊飾鍊波動。
- 鏡像擺放的部件（翻轉重複使用的圖）會自動修正網格繞向。

## 角色的佈線、骨鏈與起始姿勢（ADR-024）

- **每個顯示部件都要有網格**：方案加 `meshing: { all: true }`，顯示中的 region 部件會依人工佈線建網格、剛性掛在原本的骨上。
  - 人工佈線（ADR-041，量自 205 個人工網格）：外框點數看輪廓不看大小，把不透明輪廓以 3 % × √(圖寬 × 圖高) 的容差簡化後的角數，乘上變形係數：剛性 0.67、1–2 根骨 0.9、3 根以上 1.5。外框點落在轉角，離不透明邊約 1 px 起（點少時轉角外凸，人工中位約 3 px），仍蓋住每個不透明像素。內部點：剛性部件沒有；2 根骨以上，在部件內每個關節（子骨起點）放一排橫過部件、垂直於骨的點，骨長超過兩段外框邊時在骨中間再放一排。三角化是 Delaunay。
  - 用變形關鍵幀做偽 3D 的部件（臉、頭、鼻子；權重是剛性也一樣）在 `feature` 上加 `deform: true`（ADR-042；`motion.deforms` 裡的部件自動算）：外框至少 ×0.9，內部先放關節排，再補到 0.27 × 外框面積 ÷ 外框平均邊長²，點落在離外框約一段邊的地方。臉和翅膀人工約多 2.5 倍，用 `interiorVertices` 直接給數量。
  - 外框點間距平均（ADR-043）：人工外框邊長很平均（166 個人工網格，短於平均邊長一半的邊只佔 9 %；舊擬合佔 22 %，擠在轉角和凹口）。外框擬合到點數後，短於平均一半的邊去掉一端（取最省的一步，仍蓋住每個不透明像素），再切開最長的邊補回點數；明確給 `hullVertices` 也一樣。一張圖跨兩腿的褲子（`nearest`、`maxInfluences: 2`），褲襠兩個靠很近的外框點在腿擺動時被拉長 3 倍以上，現在不會再出現。
  - `nearest` 權重跨三根以上會交會的骨（褲襠的脊椎、大腿、小腿）時，`maxInfluences` 用 3：2 會讓排第三的骨在相鄰兩點間一步歸零（大野狼褲子 0.5.6 佈線，`maxInfluences` 3 拉伸 0.90，2 是 3.26）。
  - 會變形的部件（身體、臉）也用 `feature` 預設的人工佈線，骨數取自它的權重（chain、gradient、nearest、dome、transfer 的來源骨），挖空（眼窩）會保留成鎖定的環。需要更密時直接給 `hullVertices` / `interiorVertices`；`density: "fine"`（約 100 點，不看大小）只在 B1/B3 變形檢查不過時才用。
  - 關鍵幀：建置最後會把每條骨軌道清成最少的關鍵幀，誤差在 `motion.keyTolerance`（預設 0.25 度或 px）內；`0` 保留全部。
  - 要交給美術繼續改的檔，改用 `motion.keyReduction`（ADR-044）：編譯保留全部 Key，再用官方 Runtime 比對世界座標頂點精簡。`fidelity` 留最少的原有 Key；`posable` 讓一起轉折的骨共用姿勢格、新 Key 在整數幀，跟隨部件保留自己的轉折與延遲。上限是世界頂點 px（預設骨架高度 0.1%／0.3%），超過就補 Key 或恢復原通道，不放寬。已有的 Spine 檔用 CLI `reduce-keys`（或 `autospine_reduce_keys`），兩種模式各出一份並附報告、預覽與 Spine 匯入匯出驗證。
- **軟的長條部件**（瀏海、鬍子、耳朵、山羊鬍、流蘇）：3 骨鏈＋`feature` 人工密度網格＋骨鏈權重。idle 裡瀏海和鬍子小幅波動。不要用矩形格網 `surface`，佈線看起來像沒做完。
- **跨關節的網格**掛在關節兩側的骨：頸部 `spine→head`、長袍 `base→spine`。掛在關節自己的骨上，藏在下面的那端會甩開。
- **起始姿勢**：
  - setup 疊了多組姿勢時，動畫不一定從 setup 開始（馬年魚 idle 的頭偏了半個頭寬）。請委託人給一張目標姿勢的圖。
  - 用 `autospine_fit_pose`（CLI `fit-pose`）擬合，把結果的 `pose` 放進 `motion.animations[].pose`。參考圖要涵蓋 `qa.view`，比例不限。
  - 臉部骨不擬合，表情（人工用 deform 改的嘴型）不在範圍內。
  - A6 檢查第 0 幀姿勢：每個部件相對人工的平均偏移，中位數 ≤ 0.03、第 90 百分位 ≤ 0.1 頭寬（暫定）。

## 有邏輯的角色骨架（ADR-025）

每根骨從自己的關節指向下一個關節，鏈條連續，骨架畫面看得出身體結構：

| 部位                 | 骨                                                                                                                                                      | 關節                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| 地面                 | `base`，在骨盆正下方                                                                                                                                    | `align(x: pelvis, y: feet)`                                      |
| 臀、軀幹             | `body`（呼吸主骨）在骨盆；`spine` 骨盆→胸；`chest` 胸→頸根                                                                                              | 骨盆在兩腿上端中間，胸在中點                                     |
| 頸、頭               | `neck` 頸根→頸頂；`head` 頸頂→頭頂                                                                                                                      | 部件重疊處                                                       |
| 腿                   | 垂直的 `stance`（地面→骨盆），用 `squash` 的 `track: true` 跟著臀部壓縮；每條腿 `thigh`（臀→膝）、`calf`（膝→踝）掛在上面；`foot`（踝→鞋底）掛在 `base` | 臀 `align(x: 腿上端, y: 骨盆)`；膝 = 褲與襪重疊處；鞋底 = 最低端 |
| 手                   | 從 `chest`：肩→肘→腕→手；手靠在身上用 IK 掛在 `body`                                                                                                    | 部件重疊處與端點                                                 |
| 軟的長條             | 從附著端長出的 3 骨鏈：頭髮、耳朵、鬍子、尾巴、鬃毛                                                                                                     | `chain.from`／`chain.near`                                       |
| 同一張圖上的多個吊飾 | 每個吊飾一條 3 骨鏈，從吊點到末端，權重用 `nearest`                                                                                                     | 各側 `end`                                                       |

- 權重跟著骨：長袍、裙子蓋在腿上時用 `base→spine` 漸層（站姿骨在同一段高度壓縮腿）；褲子用大腿、小腿骨鏈；襪子與鞋用 `calf→foot` 漸層；頸部 `chest→head`。會變形的軀幹網格比人工中位數密。
- 不要用 `sink.legs`：它沿大腿方向縮短，外八的腳會往內滑。
- 接縫量測（B2）只算看得到的接縫：上層部件的外框壓在下層的那一圈。

## 一個骨架裡有多組姿勢（ADR-021）

- 遊戲角色常把多組姿勢放在同一個骨架，setup 只顯示其中一組。例如薑餅人 setup 是 `Idle_*`，呼吸 idle 用的是 `Drop_*`。
- 先確認每個動畫顯示哪些 slot。這是委託人會交代的資訊；盲測時只讀附件開關。
- 在動畫上用 `show` 列出要顯示的 slot（或 `slot#attachment`），用 `hide` 列出要隱藏的 slot。
- setup 隱藏的 slot 只有一個附件時，關節、網格、臉部與探針可以直接寫 slot 名稱。
- 同一動畫中途換圖（眨眼、嘴型）用 `motion.swaps`（ADR-027）：指定第幾幀換成哪個附件或隱藏。
- 同一角色的多段動畫最後用 `merge-plans` 合成一份方案、建一個 Spine 專案（ADR-031）；各單次動畫的 `move` 骨要用同一個支點。
- 進場、退場、勝利等單次動畫（ADR-030）：`animations[].loop: false`，用 `keyed` 的縮放、位移、旋轉關鍵幀和 `colors` 淡入淡出；最後的值會停住，不回到第 0 幀。一個單次動畫一份方案，`cycle` 等於它的幀數。
- 單次動畫有關鍵姿勢圖時（分鏡或參考影片截圖，ADR-033）：
  - 先用不含「依名稱猜的大動作」的方案建置（例如拿掉 `move` 骨的跳躍 `keyed`），呼吸、跟隨、波動留著。
  - `autospine_fit_pose` 給 `references: [{ frame, path }]`，每張圖在自己那一幀、疊在建置的動作上擬合；結果的 `keyposes` 放進 `motion.animations[].keyposes` 再建置。關鍵姿勢之間用 `ease`（可用 `ease` 參數改），第 0 幀沒給就是原姿勢，單次動畫停在最後一個關鍵姿勢。
  - 第 0 幀那張就是起始姿勢時（已經用它擬合過 `pose`）給 `zeroFrame: 0`：它不產生關鍵姿勢，比對在它上面的誤差（例如褲子網格彎得和人工不同）會從其他圖扣掉。
  - 覆蓋率低於 0.6 的圖不採用（`minCoverage` 可調）；`ignore` 可排除換了畫法的部件（表情的嘴、眼、舌頭）。
  - 擬合不到：表情與網格變形（吐舌頭、瞇眼、臉皮變形）、縮放、人工把手移離手臂的位移、被蓋住的部件；表情一變，臉部部件太多時整顆頭可能對不上。
  - 對著新建置再擬合一次可以再修正（輸出已含原本的關鍵姿勢）。

## 動作先驗值（ADR-032）

2026-10 批次 68 段人工動畫（19 個檔案、15 套美術）在官方 Runtime 上量出的中位數與範圍。這是先驗值，不是目標：同一項在不同角色可以差到 10 倍。簡述、參考或使用者指定的值優先。數值都在 `@autospine/motion` 的 `MOTION_PRIORS`：

- `oneShotTemplate(動畫名稱, { frames, unit: 頭寬, subject: "character" | "prop" })`：依名稱選模板，回傳 `move` 骨的 translate、scale、rotate 關鍵幀、顯示部件的透明度、頭部張望，以及四肢與長條的擺幅和建議的關鍵幀間距。
- `loopRecipe("idle" | "walk" | "prop", 頭寬)`：循環的寫法，例如 idle 的臀部深度、頭部跟隨與長條擺幅。

| 類別（動畫數／美術數）    | 人工                                                                                                    | 我們原本                         |

## 循環的驗收指標（ADR-020）

- 循環動畫看不出從哪一幀開始，所以 `compare-reference` 與 `optimize-motion` 用循環模式量 D1：
  - `range:<探針>`（高度範圍）取代峰值時間與過衝。
  - `lag:<探針>`（相對身體的循環延遲，只在半個週期內找）取代峰值延遲。
  - 手部範圍用全部幀。
- 舊的 D1 數字（例如 16 項中幾項）是以一次性動作的方式量的，不能和新的 13 項直接比較。
- 盲測的節拍比對若是循環，先找最佳循環平移再算 F1，規劃與等距、隨機基準一律同樣處理，另附原始 F1。

## 量測與參考值

每次修改權重或動作後，用 `autospine_measure_overlap` 在動作的極值姿勢量測。試作達到的值只能作比較，不是通過門檻：

| 量測                        | 本流程（木乃伊貓試作）                 | 對照                                 |
| --------------------------- | -------------------------------------- | ------------------------------------ |
| idle2 臉部位移 x／y（頭寬） | 0.064／0.054                           | 人工 0.061／0.056；原版 0.034／0.002 |
| 光暈離開表面 idle2／`in`    | 2.3／5.0 px（四肢改骨鏈後腿部 8.3 px） | 剛性光暈 50.4／77.3 px               |
| 手肘／膝蓋接縫（最差動作）  | 7.2–7.8／6.7–10.7 px                   | 一圖一骨最高 72.4／67.0 px           |
| 閉眼幀眼皮離開眼白          | 0 px                                   | 眼白也用圓頂權重時 17.7 px           |
| 眼窩緣滑移 臉底／繃帶       | 0／≤ 3.2 px                            | 未加 pins 時 14.8–21.3 px            |

## 目前限制

- 自動節拍規劃（`planBeats`）**兩次盲測都未通過**（2026-10-13）：
  - pig：容許 3 幀的 F1 為 0.077，低於等距的 0.154。
  - 雕像：F1 為 0.333，與等距相同。
  - 主要誤差是段落結構猜錯，以及「哪一層會動」判斷錯，不在時間比例。
  - 延遲與循環規則已依 pig 結果修正，但還沒有在有循環本體動作與骨鏈、且沒看過的角色上驗證。
  - ADR-032 的先驗值同樣只在看過的檔案上量過，盲測前不算驗證。
  - 結論：有參考或指定時間點時以參考為準；規劃器只是起始值，不是人工水準的時間。
- 圓頂場為軸對齊橢圓，頭部大幅傾斜需要旋轉場（未實作）。
- 同一通道不能疊加兩個動作，需拆成不同骨。
- 不支援單鍵分通道緩動。
- 光暈誤差隨來源網格粗細而增加。
- 特徵環網格（臉部，未指定密度時）的外框比人工密（70–91 點對 22 點），最小角約 7°。
- 表情用 deform 改的部分（例如閉嘴）還不能從圖片或需求得知。
- 數值通過與官方往返成功都不等於美術品質通過。
