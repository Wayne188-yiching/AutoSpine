# 角色製作流程與執行能力

日期：2026-10-08。76 部教學的完整音訊轉錄文字已研讀，另有重點畫面抽查；能力表依實作與測試核對，不是人工逐字核聽或全角色品質驗收。

## Skill、MCP 與引擎

- `autospine` Skill 統籌部件辨識、骨架、佈線、權重、約束、控制器、動畫與驗收的判斷。依工作階段讀取相關規則，保持同一角色與輸出版本的關聯。
- AutoSpine 引擎計算網格、骨架、權重與動態，輸出規格並提供診斷。Skill 不重寫數學引擎或自行拼裝 Spine JSON。
- `autospine` MCP 將已開放的引擎流程提供給助手呼叫。CLI 是同一套引擎的另一個入口。
- 現有另一個 `spine` MCP 提供 JSON 檢查、patch 預覽／另存、差異稽核與官方 CLI round-trip。這些檔案工具不代表可以即時操作 Spine Editor 的每個介面功能，也不等同 AutoSpine MCP。

## 接到角色任務時

先確認輸入的組裝座標、版本、附件身份與用途；依現有允許模式選擇工具。單張 PNG 本身不提供全角色相對位置。圖片＋名稱＋構圖提案的依據要保留，人工評分與參考幾何不代填自動生成答案。

依實際支援範圍完成以下工作；缺少工具能力時記錄需要接入的功能，不將教學中的操作名稱改寫成不存在的 MCP 工具：

1. **控制方案**：決定主體關節、次要骨鏈、剛性附件與控制骨的分工，保留不確定原因。關節由連接與活動需求支持，圖片路徑只提供候選線索。
2. **佈線**：按變形區域配置頂點與連線，檢查輪廓覆蓋、三角形有效性、接合位置與可編輯性。從主彎曲方向測試拓樸，不只看靜態密度。
3. **權重**：確認附件對應的變形骨，再求解、平滑與限制影響數；驗證每個頂點覆蓋、正規化及 setup pose。剛性飾物與髮束不得因距離接近就自動共享所有影響。
4. **IK 與控制器**：檢查控制目標、父子關係、彎曲方向與驅動衝突。使用支援的約束模式，並分別標示中立 baked pose 或 Spine 原生約束輸出。
5. **動態**：關節掃動只用於 Rig 診斷；正式製作依 [Layout → Blocking → Final](pose-first-workflow.md)，先 Key 主要 Pose，再補 breakdown 與節拍，最後加曲線、次要部件延遲與細節。製作前檢索相關已研讀動畫參考，每階段保留計畫、Pose 圖與預覽並自評；檢查根部漂移、過度拉伸、露縫、塌陷、翻折和圖層錯誤。自評通過後自主接續，不新增逐階段人工核准要求。
6. **交付**：保留來源、另存輸出、核對對應 Runtime／Editor 的實際結果。工程測試、Rig 結構、變形品質與表演品質分開判定。
