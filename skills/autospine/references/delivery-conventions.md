# 遊戲執行環境的 Spine 交付規範

要交給遊戲程式（Cocos Creator、Unity）的 Spine 檔，進引擎前要符合的版本、命名、結構與上限。這是通用的 Spine 遊戲交付慣例（ADR-053）；專案若有自己的規範，以專案為準，數字不同時兩邊都告訴需求者，不要自己選。

標 **自動** 的規則由 `check-delivery` 檢查（`deliver --target` 交付時也會跑一次，只報告不擋交付），規則代號就是報告裡的代號。其餘要看 Spine 介面、圖片或影片，列進交接說明請需求者確認。

```text
node <skill>/scripts/autospine.mjs check-delivery <skeleton.json|project.spine> --target=cocos|unity|unity-4.1 [--kind=<類型>] [--large-board] [--export=<匯出資料夾>]
```

MCP：`autospine_check_delivery`（只讀工作區內的 JSON；`.spine` 與匯出資料夾用 CLI）。結束碼 2 表示有錯誤。

## 執行環境

| `--target`  | Spine 版本 | 二進位骨架    | Atlas        | 名稱可用字元         | 遮罩              |
| ----------- | ---------- | ------------- | ------------ | -------------------- | ----------------- |
| `cocos`     | 3.8.99     | `.skel`       | `.atlas`     | 英文、數字、`_`      | 一個骨架最多 1 個 |
| `unity`     | 4.0.56     | `.skel.bytes` | `.atlas.txt` | 英文、數字、`_`、`-` | 不用              |
| `unity-4.1` | 4.1.24     | `.skel.bytes` | `.atlas.txt` | 英文、數字、`_`、`-` | 不用              |

- **V1 自動**：專案用該環境的 Spine 版本製作與匯出。`.spine` 會先用目標版本開；開不了表示是更新的編輯器做的，改用製作的版本匯出，再報 V1。
- 4.x 降到 3.8：先取消「分開」(split) 的位移與縮放 key，匯出 3.8 用的 JSON 再匯入，重新指定圖片路徑，補回曲線。AutoSpine 的 `deliver --target=cocos` 用 3.8 版面交付，3.8 放不下的東西會停在 `SPINE_38_UNSUPPORTED`（ADR-047）。

## 檔案與資料夾

- 一個項目一個 `.spine`。要一起演出、共用貼圖、前中後層、高度互動或前導動畫的才放同一檔；換色用 Skin，不分檔。
- 資料夾：`.psd`（不存成 PSB、不超過 2 GB）、`.spine`、`Images/`（刪掉沒用到的圖）、`Previews/`（.mp4）、`Export/`。
- 貼圖來源是 `./Images`，依 Skeleton 分子資料夾。
- Spine 檔名 = 第一層 Skeleton 名稱。

## 命名

- **N1 自動**：骨頭、插槽、附件、動畫、Skin 只用英文、數字、`_`（Unity 另可 `-`）；不可中文、空白、特殊字元。圖片路徑可以有資料夾 `/`，其他名稱不行。
- 首字大寫，左右統一用 `L` / `R`，分類加前綴（例如 `FG_`）。
- **S2 自動**：Additive 插槽名稱要有 `_Add`；名稱有 `_Add` 卻不是 Additive 會提醒。
- 參考用的骨頭、插槽、附件以 `_` 開頭，而且不匯出（**E3 自動**：合圖裡有 `_` 開頭的圖會提醒）。

## 擺放

- 角色左右置中，腳底在原點。
- Symbol 靜態圖置中在 (0,0)，動畫第一格 = 靜態圖；Setup 要和 2D 設計圖完全一致。
- 其他物件置中在 (0,0)。

## 骨架

- **R1 自動**：root 不位移、不旋轉、不縮放。
- **R2 自動**：root 不設 key。
- **R3 自動**：root 下只放一根 `Actor`，所有物件都掛在它下面（`_` 開頭的參考骨除外）。`deliver --target` 會自動插入 `Actor`，把 root 的變形、key、子骨、插槽與約束都移過去，世界座標不變。
- **W1 自動**：軟綁時一個頂點最多綁 5 根骨頭，用 Prune 清掉多餘權重。
- 骨頭數、三角面數要有效率（上限見下表）。

## 貼圖

- Cocos 1:1 製作。Unity 用 2 倍（例如 2440×1440）製作，輸出時縮 0.5。
- 不可有多餘的透明邊；特效圖不可是黑底；Mesh 過的圖不能再改範圍；斜的圖要轉正。
- 模糊光暈可以縮到 50–80 %。跨骨架使用同一張貼圖時要一致。
- 少用序列圖；純序列圖改用引擎的動畫。

## 插槽、遮罩

- **S1 自動**：混合模式只用 Normal 與 Additive；同混合模式的插槽排在一起，減少 draw call。
- **S5 自動**：刪掉空的插槽與附件。不暫時隱藏插槽。可以用 Tint。
- **S3 自動**：不用 Point 附件。
- **S4 自動**：遮罩（Clipping）非必要不用。Cocos 一個骨架最多 1 個，點數 4（最多 8）；Unity 不用。遮罩內的三角面越少越好（上限見下表，要在 Metrics 看）。
- **U1 自動**（Unity）：Setup 至少顯示一張圖，而且不能只顯示 Additive 圖。

## 多國語系文字與變動數字

- 不對字形做特效或逐字動畫；一串字一張圖。
- `HP_` 開頭的骨頭下只放語系文字或字型數字（**T1 自動**）。
- 這些附件不位移、縮放、旋轉；名稱含 `TEXT` / `NUM`，以 `_` 開頭，例如 `_HP_TEXT1`（**T1 自動**）。
- 顯示與否用插槽透明度，不用附件可見性 key（**T1 自動**）。Unity 換語系用 Skin。

## Setup 與動畫

- 2D 對位圖保留在 (0,0)、不變形、不匯出。
- 額外特效和替換部位在 Setup 關閉，動畫第 0 幀要 key（**A1 自動**：插槽的顏色、透明度、附件 key 不是從第 0 幀開始會提醒）。
- **A2 自動**：Loop 動畫頭尾姿勢一致（名稱含 `loop` 或 `idle` 的動畫，結尾那格與第一格不同會提醒）。
- **A3 自動**：串接動畫（`_In` / `_Loop` / `_Out`、`_Start` / `_End`）第一格不留空，各段有 key 的欄位要相同。
- 不用 Clean Up。有 Track 的要用 Preview 驗證。動態風格符合 2D 設計，全身協調。

## 依類型的動畫

- **K1 自動**（`bigwin`）：小於 10 倍用 `YouWin_Start` / `YouWin_End`；10 倍以上依階段 `BigWin`、`MegaWin`、`SuperWin`（再加 `GoldenWin`，或 `MarvelousWin`、`LegendaryWin`），每階都有 `_Start` 與 `_End`。Start 從原尺寸持續放大到 1.05 倍；End 先放大震一下再收掉；下一階的 Start 從上一階的畫面轉變；分數數字在過程中不可消失；不用做壓暗底圖。
- **K1 自動**（`loading`）：每一頁的資源放在該頁的骨頭下，骨頭與動畫都叫 `Page_01`、`Page_02`…（第一頁 = `Page_01`）。最高贏分頁放第一頁，範本的 `WIN_UP_TO`、`Text`、`Num` 骨頭保留：可調 `WIN_UP_TO` 的位置與大小，`Text`、`Num` 不動（保持旋轉 5 度）；對位用的字圖與數字圖不匯出。

## 輸出

**Cocos**

- 二進位 `.skel`，不勾「非必要資料」；`.atlas`。
- 合圖長邊 ≤ 2048（**E2 自動**）。勾：刪除空白、旋轉、去除重複、出血、外圍間距、重複間距、限制記憶體；不勾：忽略空白圖片、2 次方、能被 4 整除。間距 2（最多 4）。
- 2 倍製作時 root 與合圖縮 0.5，把縮放值寫在 root 的名稱裡。對位圖、參考圖取消匯出。

**Unity**

- `.skel.bytes`、`.atlas.txt`（**E1、E2 自動**）。
- 合圖最大 2048，勾 2 次方與正方形（**E2 自動**）、限制記憶體。Symbol 一起合圖。

**E1 自動**：骨架檔的副檔名與匯出版本；匯出資料夾裡有 JSON 會提醒（遊戲讀二進位）。
**E2 自動**：合圖頁面大小、Unity 的 2 次方正方形，以及該類型的合圖長邊上限（超過只提醒）。

## 回傳內容

- `.spine` 編輯檔、Skeleton Viewer 錄的預覽影片；多段動畫（In / Loop / Out）串接成一支。
- Symbol 與 Icon 錄 3 秒：2 秒動畫加 1 秒靜止。Loading 頁錄 2 次。
- 貼圖容量計算與 Spine 資源檢查器（Metrics）的截圖。

## 容量與畫面

- Cocos 總貼圖 10 MB 以內最好，最多 15 MB（以 WEBP 品質 90 計）；輕量遊戲 5 MB 以內。或約 6–9 張 2048² 合圖。
- 顯示範圍不超過 6000×6000。

## Symbol 靜態圖（用 Spine 匯出 PNG）

- 找出全部 Symbol 的最大尺寸；匯出 PNG 勾裁剪，中心點 = 尺寸 ÷ 2（負值）。
- 尺寸必須是偶數，否則進引擎會偏一像素。
- 縮小後失真時，縮放設 200，再到 Photoshop 縮 50 %。

## 檢查不到的

- 遮罩內三角面、動畫高峰的三角面、實際 draw call：Spine 的 Metrics。
- 貼圖容量：PNG 原檔大小不等於 WEBP 品質 90 的容量。
- 圖片內容（透明邊、黑底、斜圖、失真）、Setup 是否和 2D 圖一致、動態風格：看圖與影片。
