# ADR-010 — per-key interpolation curves in AnimationSpec

Context: pose-to-pose animation (few keys, eased segments, held poses) could not be expressed. AnimationSpec keys carried only time and values, every adapter emitted linear keys, and callers therefore baked dense samples. In the 2026-10-08 mummy-cat review, v17 `idle2` needed 6,777 linear bone keys plus 3,615 deform keys, while the hand-made file used 1,618 keys with Bezier and stepped segments. ADR-008 deliberately kept curves as scalar functions outside the IR.

Decision: add an optional `curve` to every rotation, translation, scale and deform key of AnimationSpec 0.1, and to `colorTimelines` and `deformTimelines` keys of the character adapter input. A curve shapes the segment from its key to the next; omitted means linear. Allowed values are `{ "type": "linear" }`, `{ "type": "stepped" }` and `{ "type": "bezier", "x1", "y1", "x2", "y2" }`. Bezier handles are normalized per segment (x is the time fraction in [0, 1], y the value fraction in [-10, 10], so overshoot is allowed). This is the form `evaluateCurve` already used: engine-neutral and unaffected by adapter sign or unit conversion. One curve applies to all channels of a key. A curve on a final key has no segment and is rejected (`ANIMATION_CURVE`, `SPINE_TIMELINE`, `SPINE_CHARACTER`) instead of being dropped.

Implementation: `sampleAnimation`, `rotationsAt` and loop validation use `keyFraction`. The weighted and character adapters convert to Spine 4.0 absolute handles per channel after their own conversions: rotation and translation y are negated, rgba uses 0..1 components and deform uses Spine's 0..1 blend space. The Gate 1 minimal adapter stays linear-only and reports `TIMELINE_CURVE` for non-linear curves.

Evidence: `tests/key-curves.test.ts` covers the schema, sampling semantics, final-key rejection, official spine-core parity and the Gate 1 rejection. spine-core 4.0 flattens each Bezier into 10 line segments. For the tested handles it deviates from the exact curve by 0.6–1.4% of the segment change, and the compiled export adds no measurable error on top. The runtime stores key times as float32, so a query exactly at a key time can still read the previous segment. A compiled character using every curve kind was imported and exported by the Spine 4.0.64 editor CLI; all 10 curves came back intact (largest handle difference 9e-16).

Consequences: presets still bake samples and are unchanged; a key-pose authoring layer can now emit sparse keys. The schema version stays 0.1 because the change is additive. Documents without curves compile to identical output, as the existing golden tests confirm. Per-channel easing (different curves for x and y of one key) is not supported. Rollback: remove the optional field and the two conversions.
