02 · WORKFLOW

工作流

  1. 1

    PSD → SPINE

    匯入 PSD

    美術把 PSD 匯入 Spine，部件拆好、擺好位置即可；骨架、佈線、權重、動作都還不用做。

    盲測時是把美術的 Spine 檔拿掉這些，模擬這一步。

    產出：只有圖片與擺位的 .spine

  2. 2

    需求

    說明要做什麼

    1. 動畫名稱與長度
    2. 這段動畫顯示哪些部件
    3. 有姿勢圖就附上（可選）
  3. 3

    AUTOSPINE

    自動製作

    1. AI 依技能寫出方案
    2. 建出骨架、網格、權重、動作，對齊姿勢圖
    3. 輸出檢查影片：佈線 → 骨架 → 動作

    產出：Spine JSON ＋ 檢查影片

  4. 4

    SPINE 專案

    交付

    1. 同一角色的動畫合成一個專案
    2. 附接手說明 HANDOVER.md，交付時在對話中摘要
    3. 有美術版時，自動比對出分數與並排影片

    產出：.spine ＋ 檢查影片 ＋ HANDOVER.md（在 _work/builds/）

可重複執行改需求或方案後重跑 3 → 4，就是新的專案。

03 · TOOLS

一個 Skill ＋ 一個 MCP

AI 照 Skill 的步驟，呼叫同一個 MCP 伺服器裡的工具；每個步驟一個工具。

SKILL

autospine：操作手冊

告訴 AI 先問清楚什麼、骨架怎麼排、照什麼順序做。

MCP

AutoSpine MCP：一個伺服器

提供下面這些工具；AI 依步驟呼叫，只讀的工具不需要寫入權限。

依步驟分組的工具

  • 步驟 3 · 寫方案lint_character_plan檢查方案
  • 步驟 3 · 製作build_characterfit_pose建出 Spine 檔、對齊姿勢圖
  • 步驟 3 · 檢查review_video佈線 → 骨架 → 動作影片
  • 步驟 4 · 交付merge_plans同一角色合成一個專案
  • 步驟 4 · 驗收compare_reference和美術原檔比對
  • 外部Spine 4.0.64ffmpeg匯出／匯入專案、輸出影片

背後的想法

  • 只看像素 關節由部件的端點、重疊、質心決定
  • 有邏輯的骨架 每根骨從自己的關節指向下一個關節
  • 人工密度的網格 點數比照美術習慣，權重依用途選
  • 稀疏關鍵幀 主動作加規則推出的次要動作，不烘焙逐格

05 · HANDOVER

美術可以直接接手

產出就是一般的 Spine 專案，只用 Spine 的標準功能，打開就能改。

專案→一個角色一個 .spine循環與單次動畫都在同一個專案裡
骨架→依用途上色骨名就是部位名，看顏色就知道用途
網格→人工密度點數與權重比照美術習慣
動作→稀疏關鍵幀＋曲線可以直接拖關鍵幀、調曲線
約束→標準 IK、Transform沒有外掛，沒有逐格烘焙
說明→HANDOVER.md在 _work/builds/，用文字編輯器開；寫每根骨的用途、每段動畫打了什麼、要改去哪裡
  • 主骨：動作主控
  • 控制骨：沒有圖片，只驅動
  • 跟隨骨：五官與圖層
  • 骨鏈：頭髮、尾巴、飾品
  • 關節骨

06 · GAPS

目前的差距

結構已經穩定，差距集中在「動得像不像美術」。

動作風格

節奏與幅度和美術差很多：循環的身體起伏常常太大，跳躍、蓄力又太小；單次動畫只能依名稱推測。

起始姿勢

進場第 0 幀常是透明、縮小或換了部件組，姿勢圖對不上，只能用 setup 姿勢。

特效

龍、金幣、粒子這類大量部件飛行的段落，純圖片沒有軌跡資訊，只能播序列與淡入淡出。

分數不等於美術認可

自動驗收只看結構與量化指標；動作好不好看，請以影片和美術判斷為準。
